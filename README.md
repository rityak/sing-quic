# sing-quic

Протокол hysteria2.

Форк [metacubex/sing-quic](https://github.com/metacubex/sing-quic) для [miray](https://github.com/rityak/miray). Наш код — в ветке `miray`.

## Что изменено

- Клиент hysteria2 обрабатывает принятые датаграммы по порядку. Раньше на каждую запускалась горутина, и датаграммы одного потока приходили переставленными.
- Заголовок UDP-сообщения hysteria2 пишется и читается напрямую, без рефлексии и лишних аллокаций. Формат тот же.
- Обфускация Salamander без аллокации на пакет: XOR идёт словами, ключ считается без копии в куче, буферы из пула. Формат тот же.
- Linux: Salamander больше не выключает в quic-go GSO, пачечный приём и GRO — каждый сегмент пачки получает свою соль, на проводе это обычные датаграммы Salamander. Выключается `MIRAY_SALAMANDER_OOB=off`.
- Клиент hysteria2, закрывая TCP-поток до ответа сервера, закрывает только отправку, как официальный клиент: сервер успевает ответить и доставить загрузку.
- Сервер hysteria2 доставляет загрузку клиента, который перестал читать до ответа (STOP_SENDING): ошибка записи ответа не обрывает соединение, как у официального сервера.
- Сервер hysteria2 на `Close` закрывает принятые соединения с CONNECTION_CLOSE, как sing-box на остановке: клиент переподключается сразу, а не по idle-таймауту.
- Сервис hysteria2: `Start` и `Close` не гоняются за слушателем; `Start`, пришедший после `Close`, сразу закрывает свой слушатель.
